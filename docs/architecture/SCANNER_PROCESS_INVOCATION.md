# Safe Scanner Process Invocation

The worker constructs a `sandbox.ProcessInvocation` with one approved absolute executable and an argv slice. The OCI runtime receives those values as separate process arguments through `exec.Command`; no shell is started and no user string is parsed as command text. `Spec.Validate` binds the executable to the scanner ID (`/zap/zap-baseline.py` for ZAP Baseline and `/nuclei` for Nuclei). Unknown scanner IDs, alternate executables, shell paths, NUL arguments, invalid HTTP(S) targets, URL userinfo, and fragments are rejected.

Invocation arguments come from the versioned `ScannerConfigV1`, after strict unknown-field rejection and scanner-specific validation. ZAP receives a bounded Baseline invocation with only generated numeric spider settings. Nuclei receives a fixed curated-template path, the configured severity allowlist, request rate, concurrency, timeout, JSONL output, and disabled update checks. User-provided command-line arguments, executable paths, template paths, ZAP hooks/config URLs, and credentials are not accepted. Target URLs are passed as one argv element; URL syntax such as quotes or shell metacharacters cannot become shell syntax.

The container receives only Kelvin job, tenant, and assessment identifiers. The host OCI runtime subprocess inherits only its required runtime configuration variables; unrelated process environment variables are filtered. No target credentials are supported or placed in process arguments. The worker applies the job deadline, container UID/GID `10001`, dropped capabilities, `no-new-privileges`, read-only root filesystem, bounded tmpfs, and resource limits. Container stdout and stderr each have a fixed 4 MiB capture ceiling enforced during writes; excess bytes are discarded and marked with a truncation suffix. Exit code, duration, timeout, cancellation, and OOM state are returned separately.

Tests exercise malformed targets and config, scanner/executable allowlists, argv preservation, bounded output, environment filtering, process failure, and cancellation. Scope validation and egress enforcement remain independent worker/runtime controls; process argument validation does not grant target authorization.

Scanner CLI references: [ZAP Baseline options](https://www.zaproxy.org/docs/docker/baseline-scan/), [Nuclei usage](https://docs.projectdiscovery.io/tools/nuclei/running).

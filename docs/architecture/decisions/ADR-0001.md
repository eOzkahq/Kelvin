## 1. Context and Problem Statement

Kelvin requires a backend runtime and web framework for the API control plane, job orchestrator, scope engine, and findings service. The chosen stack must:

* Support long-running asynchronous scanner worker orchestration with bounded timeouts.
* Provide strong typing and compile-time safety to reduce security-critical bugs.
* Offer mature, security-vetted libraries for TLS, authentication (OIDC/SAML), RBAC, and rate limiting.
* Execute in rootless containers with minimal attack surface.
* Allow the security team to perform static analysis and dependency auditing.

Informal decisions risk "resume-driven development," conflicting libraries, and architectural drift. This ADR records the foundational backend choice.

---

## 2. Decision Drivers

| Driver | Priority | Rationale |
| :--- | :--- | :--- |
| Security isolation & small attack surface | Critical | Scanner platform is a high-value target; minimal dependencies reduce CVE surface. |
| Strong static typing & compile-time safety | High | Prevents entire classes of input-validation and authz bugs. |
| Mature security libraries (TLS, OIDC, RBAC) | High | Avoids rolling custom crypto/auth. |
| Async concurrency for worker orchestration | High | Thousands of concurrent jobs across distributed workers. |
| Container-friendly (rootless, low overhead) | High | Workers run in hardened rootless containers. |
| Team familiarity & hiring pool | Medium | Reduces onboarding and maintenance friction. |
| Long-term maintainability & vendor neutrality | Medium | Avoids lock-in to a single commercial vendor. |

## 3. Considered Alternatives

| Alternative | Pros | Cons | Verdict |
| :--- | :--- | :--- | :--- |
| **Go (Golang) + standard library / Gin or Echo** | Compiled to single static binary; excellent stdlib (net/http, crypto); strong concurrency model (goroutines/channels); mature security tooling (govulncheck, staticcheck); rootless container-friendly; small memory footprint | Less expressive type system than Rust; GC pauses (minor for I/O-bound control plane) | **Selected** |
| Rust + Actix-web / Axum | Memory safety without GC; strongest security posture; excellent performance | Steeper learning curve; slower compilation; smaller library ecosystem for OIDC/SAML; higher onboarding cost | Rejected (Phase 1); revisit for Phase 6 high-performance workers |
| Node.js + TypeScript / Express or Fastify | Large talent pool; fast development; rich npm ecosystem | GC pauses; larger dependency tree; historically higher vulnerability density in transitive deps; less ideal for CPU-bound scanner orchestration | Rejected |
| Python + FastAPI / Django | Fast development; rich security ecosystem | Interpreted; GIL limits true concurrency; larger runtime footprint; slower cold starts in containers | Rejected |
| Java + Spring Boot | Mature; strong enterprise ecosystem; strong typing | Heavy runtime footprint; slow container startup; complex tuning for rootless isolation | Rejected |

## 4. Decision

Kelvin's core backend control plane (API gateway, auth service, scope engine, job orchestrator, findings service) is implemented in **Go (Golang)** using the **Go standard library** as the primary HTTP framework, supplemented only by vetted third-party modules for:

* OIDC/SAML authentication (e.g., `golang.org/x/oauth2`, `crewjam/saml`)
* Structured logging (`go.uber.org/zap`)
* Configuration management (`spf13/viper`)
* PostgreSQL driver (`lib/pq` or `jackc/pgx`)
* Redis client (`redis/go-redis`)

**Constraints:**
* Go version: 1.22+ (minimum supported version at time of adoption).
* All dependencies pinned via Go Modules with `go.sum` verification.
- No dependency may introduce a transitive CVE with CVSS ≥ 7.0 without a documented exception.
* Backend services compile to statically linked, rootless-container-friendly binaries.
* All new code passes `golangci-lint`, `staticcheck`, and `govulncheck` in CI.

---

## 5. Consequences

### Positive Consequences
* Small, auditable dependency surface reduces supply-chain risk.
* Compiled static binaries simplify rootless container images (distroless / scratch).
* Strong concurrency primitives fit the async job-orchestration model.
* Mature security tooling (govulncheck, staticcheck) integrates cleanly with CI.

### Negative Consequences
* Less expressive type system than Rust; requires disciplined input validation at API boundaries.
* Smaller pool of Go security specialists compared to Java/Python; mitigated by documentation and onboarding guides.
* Third-party OIDC/SAML libraries require careful review before adoption.

### Risks
* Dependency supply-chain attack (mitigated: Go Modules checksum verification, Dependabot, quarterly dependency audits).

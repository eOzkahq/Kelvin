## 2. Step-by-Step Execution Protocol

### Step 1: Worker Activation on Oracle Cloud Host
In Oracle Cloud Shell (or SSH session as `opc`):

```bash
# 1. Verify environment and canary safety invariant
sudo grep "KELVIN_CANARY_ONLY=" /etc/kelvin/staging.env
# Must output: KELVIN_CANARY_ONLY=true

# 2. Verify native worker binary exists and is executable
/opt/kelvin/bin/kelvin-worker --version || ls -la /opt/kelvin/bin/kelvin-worker

# 3. Enable and activate worker service
sudo systemctl enable --now kelvin-worker.service

# 4. Confirm active running status
sudo systemctl status kelvin-worker.service --no-pager
```

### Step 2: Confirm System Health & Runner Availability
From any client terminal:

```bash
curl -fsS https://api.eozka.com/readyz
```

Expected output:
```json
{"data":{"status":"READY","database":"UP","broker":"UP","scannerRunner":"UP","timestamp":"..."},"success":true}
```

### Step 3: Run Authorized End-to-End Canary Assessment from Vercel
1. Open [`https://kelvin-orpin.vercel.app/login`](https://kelvin-orpin.vercel.app/login) in your browser.
2. Sign in with the bootstrapped administrator credentials (`owner@eozka.com`).
3. Navigate to **New Assessment** ([`https://kelvin-orpin.vercel.app/assessments/new`](https://kelvin-orpin.vercel.app/assessments/new)).
4. **Step 1 (Target Selection):**
   - Option A: Select pre-configured **Staging Mock Target (Canary)** (`http://127.0.0.1:8080`).
   - Option B: Click the **Custom Target URL** tab and enter `http://127.0.0.1:8080`.
5. **Step 2 (Scan Profile):** Select **Standard Baseline Assessment** (or Passive Web Application Audit).
6. **Step 3 (Configuration):** Accept default rate limit and timeout.
7. **Step 5 (Scope Confirmation):** Check the mandatory authorization attestation box.
8. Click **Dispatch Assessment**.

### Step 4: Live Processing Verification
1. The frontend immediately redirects to the live assessment detail view (`/assessments/:id`).
2. The UI observes live state progression: `QUEUED` → `PREFLIGHT` → `DISCOVERY` → `SCANNING` → `NORMALIZING` → `COMPLETED`.
3. In Upstash Redis: The job is dequeued and claimed via atomic distributed lease.
4. On Oracle host: The worker launches the certified scanner container in rootless Podman/crun sandbox.
5. In Supabase: Findings are normalized, scrubbed via R1-R10 rules, and persisted in `findings` table.
6. The assessment status reaches `COMPLETED` with non-zero findings displayed on the dashboard.

### Step 5: Report Generation Verification
1. Navigate to **Reports** ([`https://kelvin-orpin.vercel.app/reports`](https://kelvin-orpin.vercel.app/reports)).
2. Click **Generate Report**, select the completed assessment.
3. Download the signed Customer Report v1 (JSON/HTML).
4. Verify cryptographic SHA-256 evidence integrity and confidentiality.

## 3. Emergency Deactivation & Rollback Procedures

If any abnormal behavior or unexpected network activity is observed:

```bash
# Immediately stop and disable worker
sudo systemctl stop kelvin-worker.service
sudo systemctl disable kelvin-worker.service

# Terminate any lingering crun/podman scanner containers
sudo podman rm -f $(sudo podman ps -aq --filter label=app=kelvin-scanner) 2>/dev/null || true

# Verify worker is dead
sudo systemctl is-active kelvin-worker.service
# Must output: inactive
```

## 3. Key Architectural Deliverables

### 3.1 Canonical Schema Normalization & Deterministic Fingerprinting (`packages/common/normalization/fingerprint.go`)
- **Normative Algorithm v1:** Produces 64-character lowercase SHA-256 digests (`v1\n<asset>\n<endpoint>\n<vuln_key>`) verifying 100% of normative test vectors in `packages/schemas/fixtures/fingerprint-vectors.json`.
- **Taxonomy Normalization:** Standardizes CWE to canonical `CWE-<number>` format and deduplicates/lexicographically sorts CVE IDs.
- **Tagged Fingerprint Parser:** Parses and validates `fp_<version>_<digest>` representation with seamless unwrapping across API and worker gates.
- **ResultValidator Completeness Gate:** 5-layer validation enforcing payload guard, structural schema, query parameter absence on endpoints, raw evidence bounds, normalization, and fingerprint integrity.

### 3.2 Evidence Redaction & Scrubbing Engine (`packages/common/redaction/redaction.go`)
- **R1-R10 Normative Redaction Rules:** Automatically scrubs Bearer/Basic auth tokens, session cookies, password form fields, API keys, JWTs, AWS keys, and PEM private keys.
- **64KiB Evidence Ceiling:** Strictly truncates inline evidence at 64KiB (`65536` bytes) with explicit truncation notices and attestation category tagging.
- **Integrity Metrics:** Automatically recomputes `size_bytes` and SHA-256 checksums on redacted evidence content.
- **Worker Pipeline Hook:** Ingested findings in `Normalizer.Normalize` are lossily scrubbed before serialization and persistence.

### 3.3 Cross-Scanner Correlation & Idempotent Deduplication (`apps/api/internal/findings`)
- **`CorrelationRepository` Interface:** Clean abstraction for managing correlation groups and memberships with multi-tenant isolation.
- **Automated Correlation:** Hooks `CorrelationRuleEngine` into `IngestionService` to cluster related findings into `CorrelationGroup` records based on shared CVEs (`RULE_COMMON_CVE`), CWE taxonomy (`RULE_SAME_ENDPOINT_CWE`), or security header baselines (`RULE_HTTP_HEADER_BASELINE`).
- **In-Batch Multi-Scanner Aggregation:** Worker `ResultValidator.ValidateBatch` aggregates secondary scanner evidence and tracks scanner provenance on overlapping findings.
- **Idempotency & Lifecycle Invariants:** Recurring scans update `last_seen_at` and `occurrence_count` without duplicate persistent findings; auto-reopens `RESOLVED` findings upon redetection.

### 3.4 Worker Result Persistence & Database Ingestion (`apps/worker/internal/daemon/sync.go`)
- **`SyncJobResults` Engine:** Extends `StateSyncer` to persist validated and normalized finding envelopes directly upon scanner job completion.
- **Tenant-Scoped Transactions:** Runs within `database.BeginTenantTx` (`SET LOCAL ROLE kelvin_app` + `SELECT set_config('app.tenant_id', ...)`).
- **Severity Counter Aggregation:** Maintains exact severity counters across `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, and `INFORMATIONAL` bands.
- **In-Memory Tracking:** `MemoryStateSyncer` tracks stored findings, occurrences, and severity breakdowns for automated tests and non-database runs.

## 3. Key Architectural Deliverables

### 3.1 Hardened OCI Sandbox Security Specification (`apps/worker/internal/sandbox`)
- **Non-Root User Enforcement:** Enforces non-root execution with numeric UID >= 1000 (standard unprivileged user `10001:10001`), rejecting system accounts (< 1000).
- **Capability Drop & Strict Whitelist:** Enforces mandatory `CapDrop=ALL`. Restricts `CapAdd` strictly to authorized raw packet transmission (`NET_RAW`/`CAP_NET_RAW`), rejecting all other capabilities (`CAP_SYS_ADMIN`, `CAP_NET_ADMIN`, `CAP_PTRACE`).
- **Tmpfs Hardening:** Ephemeral tmpfs scratch space (`/tmp:size=64m`, `/run:size=16m`) strictly enforces `noexec,nosuid,nodev`. Rejects mounting over system paths (`/`, `/etc`, `/bin`, `/usr`).
- **Workspace Isolation:** Rejects host path escapes or mounting sensitive host directories (`/`, `/etc`, `/usr`, `/var`, `C:\Windows`) into scanner containers.

### 3.2 Cgroups v2 Resource Quota Engine & Violation Metrics (`apps/worker/internal/limits`, `daemon`)
- **Cgroup v2 Bounds:** Configures `cpu.max` (`--cpus`), `memory.max` (`--memory`), and `pids.max` (`--pids-limit`).
- **Memory Soft Throttling:** Added `MemoryHigh` (`memory.high` / `--memory-reservation`) support with strict validation (`MemoryHigh <= MemoryLimit`).
- **OOM & PID Exhaustion Detection:** Enhanced OOM detection with exit code 137 and stderr inspection. Added `PIDLimitExceeded` detection for thread/fork exhaustion.
- **Metric Recording:** Worker daemon lifecycle automatically records `ViolationOOM`, `ViolationPIDs`, and `ViolationDeadline` in `metrics.Registry`.

### 3.3 Bounded Output Streaming & Parser Guard (`apps/worker/internal/outputcapture`, `parserguard`)
- **Strict 50MB Buffer Cap:** Enforces hard ceiling on stdout/stderr buffering with explicit forensic truncation marker `[TRUNCATED BY KELVIN PARSER GUARD: maximum capture buffer limit reached]`.
- **Partial SHA-256 Digest:** `BoundedWriter` and `StreamResult` compute SHA-256 digests over captured buffer bytes.
- **Parser Panic Recovery:** All JSON deserialization and streaming line scanning routines in `parserguard` wrap parser logic with panic recovery returning `ErrPanicRecovered`.

### 3.4 Container Teardown & Lifecycle Reaper (`apps/worker/internal/reaper`)
- **Orphan Container Reaper:** Queries Podman engine for dead, exited, or stopped `kelvin-job-*` containers and forcefully removes them.
- **Stale Container Termination:** Discovers running scanner containers exceeding maximum runtime (`maxAge`) and terminates them.
- **Composite Sweeper:** Coordinates database stalled job recovery, orphan container termination, and filesystem workspace purging in unified background loops.

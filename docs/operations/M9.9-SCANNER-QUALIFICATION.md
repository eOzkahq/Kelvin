## 2. Real Scanner Invocation Specifications

### 2.1 Container Sandboxing Invariants (`apps/worker/internal/sandbox`)
- **Runtime:** Rootless Podman executing through `crun` OCI runtime.
- **Capabilities:** `CAP_DROP=ALL` (no Linux capabilities granted).
- **Filesystem:** Read-only root filesystem (`read_only_rootfs: true`), transient tmpfs at `/tmp` (size: 256MB, `noexec,nosuid`).
- **Network Namespace:** Isolated namespace attached strictly to Kelvin controlled egress proxy. Direct Internet routing disallowed.
- **Resource Bounds (cgroups v2):**
  - CPU: Max 1.0-2.0 cores (`CPUQuota=200%`).
  - Memory: Max 1.5 GiB with high-watermark reclaim at 1.2 GiB.
  - Tasks: Max 256 PIDs (`TasksMax=256`).
- **Cleanup Reaper:** Automatic SIGKILL and container garbage collection on timeout or context cancellation.

### 2.2 Scanner Output Collection & Schema Normalization (`packages/common/normalization`)
1. **Raw Output Capture:** Bounded buffer streaming with 10MB parser guard ceiling, preventing memory exhaustion attacks from malicious targets or compromised scanners.
2. **Schema Normalization:** Maps scanner-specific outputs into canonical `finding.v1.json`:
   - Unique lowercase SHA-256 fingerprint: `v1\n<asset>\n<endpoint>\n<vuln_key>`.
   - Standardized CWE taxonomy (`CWE-<number>`) and lexicographically sorted CVE arrays.
3. **Sensitive Data Redaction (R1-R10):** Automatically scrubs Bearer/Basic auth tokens, session cookies, API keys, JWTs, AWS credentials, and private keys from evidence before database storage.
4. **Cryptographic Tamper-Proofing:** Inline and artifact evidence records calculate immutable SHA-256 checksums. Any single-byte modification causes immediate validation rejection.

# Critical User Journey Matrix

The 12 mandatory end-to-end user journeys defined in Section 3.C were tested across the reference environment:

| Journey ID | Persona | Title & Flow Description | Acceptance Criteria | Verified Result | Status |
|:---:|---|---|---|---|:---:|
| **UJ-01** | Standard Member | **Sign-In & Organization Entry**<br>User authenticates via credentials or OIDC SSO, receives JWT, and enters their provisioned organization workspace. | Authenticated session established; tenant context validated; user redirected to `/dashboard`. | Validated on staging; cookie secure; JWT bound to tenant. | **PASS** |
| **UJ-02** | Workspace Admin | **Assessment Creation & Profile Selection**<br>Admin selects target asset, chooses approved scan profile, and submits assessment. | Input validation passes; policy engine validates maintenance window; job enqueued in fair-share queue. | Policy gatekeeper executed AST evaluation; duplicate submission prevented. | **PASS** |
| **UJ-03** | Security Analyst | **Assessment Queue & Execution Polling**<br>User views real-time execution status of queued/running assessment without blocking UI. | Non-blocking execution state updates; accurate progress bar and worker attribution. | UI displays running state; worker slot properly allocated. | **PASS** |
| **UJ-04** | Security Analyst | **Assessment Results Review**<br>User navigates from completed scan to executive summary and full findings inventory. | Total findings, severity distribution, and scanned targets render accurately. | Severity cards (Critical, High, Medium, Low) load within 180ms. | **PASS** |
| **UJ-05** | Security Analyst | **Findings Search & Multi-Filter Triage**<br>User filters findings by severity (Critical), status (Open), and searches keyword `SQL Injection`. | Debounced search input; responsive table updates without full page reload; stable pagination. | Filter queries executed with stable sorting; pagination state preserved. | **PASS** |
| **UJ-06** | Security Analyst | **Finding Inspection & Evidence Retrieval**<br>User selects finding detail; inspects technical description and downloads sanitized evidence blob. | Evidence viewer enforces normative redaction (R1-R10); secrets, tokens, and keys masked. | Verified: Bearer tokens, AWS keys, and passwords masked with `[REDACTED]`. | **PASS** |
| **UJ-07** | Security Analyst | **Remediation Lifecycle & SLA Status Update**<br>User assigns remediation task, sets due date, and transitions status from Open to In-Progress. | SLA countdown updates; audit log records transition; state transition valid according to state machine. | Valid state transition; audit event recorded in `audit_log`. | **PASS** |
| **UJ-08** | Security Analyst | **Remediation Verification Scan Trigger**<br>User initiates follow-up targeted assessment to verify vulnerability resolution. | Targeted scan scheduled; result automatically resolves finding upon confirmed absence. | Automated follow-up test suite verified state change to `RESOLVED`. | **PASS** |
| **UJ-09** | Standard Member | **Assessment Report Generation & Export**<br>User compiles assessment report and downloads signed PDF/HTML artifact. | Report compiled from immutable snapshot; signed 15-minute download URL generated. | Verified PDF download with SHA-256 checksum verification. | **PASS** |
| **UJ-10** | Org Owner | **User, Team & Policy Administration**<br>Owner invites new user, assigns custom role, and configures maintenance-window policy. | Role permissions strictly checked; invitations audited; policy changes versioned. | Policy version incremented; audit trail emitted with actor attribution. | **PASS** |
| **UJ-11** | Compliance Auditor | **Audit Log Search & Integrity Certification**<br>Auditor searches immutable audit trail and executes cryptographic chain verification. | Search returns paginated, sanitized records; Merkle root matches signed checkpoint. | Cryptographic verification passes with `VALID` certification. | **PASS** |
| **UJ-12** | Service Identity | **Machine-to-Machine Integration Dispatch**<br>Automated runner uses OAuth 2.0 client credentials to ingest findings and triggers Slack notification. | Strict non-interactive authentication; payload secret redaction; delivery retry backoff. | Slack webhook dispatched via Block Kit with secrets redacted. | **PASS** |
